# Practice test repo: working notes for Claude

David builds numbered practice tests ("Practice Test NN": v33, v34, …) here to prepare a Year 4 child for the NSW OC placement test. One test per version, each a new button on `index.html`. Work only in this repo (`utx/prac`); never create new repos.

## Adding version NN
Use the `new-test` skill (`.claude/skills/new-test/SKILL.md`): it is the full step-by-step procedure. Summary:
1. Before writing, compare every planned question against the official sample papers, using `calibration/sample_notes.md` (own-words notes on all three papers; the papers themselves are never in the repo, see Copyright). Attached papers, when available, are a bonus for closer calibration. Check the coverage record in every `content/vNN.json` so no skill, topic or format repeats too soon.
2. Write `content/vNN.js` (defines `passMode`, `INK`, the passage/diagram constants and `SECTIONS`; see `content/v33.js` for the shape) and `content/vNN.json` (version, date, reading title, reading_format, thinking/maths skill labels, sample_map, and `categories`: one question-type label per question, chosen from `CATEGORIES` in `tools/build.py`, which the stats page groups by).
3. Held for review or published: see "Held for review, then released" below (`python3 tools/release.py`).
4. `python3 tools/build.py`, which builds `tests/vNN/index.html` and regenerates `index.html`. Never hand-edit generated files.
5. `tools/check.sh NN` (runs the build, `check_lengths` (must report 0 longest) and `check_render` (must PASS)). `node tools/question_sheet.js content/vNN.js` makes the answer-free copy for the cold solve.
6. Verify every answer by computation, then run an independent cold solve (a separate agent that never sees the answers). Fix what it finds, re-check, then commit and push.
7. Finish by giving David a list of every question mapped to the sample-paper question(s) it most relates to, and the skill being tested.

## Held for review, then released (David, Oct 2026)
- New tests are **held for David's review** while 10 or more tests are uncompleted on the student menu: `"status": "review"` in `content/vNN.json` builds the test but shows it only on the admin page ("New tests waiting for your review"), where David practises it and approves its questions or the whole test. Opened directly, a held test only says it isn't ready yet.
- When fewer than 10 are uncompleted, approved held tests are released (oldest first, topping up to 10; extras stay approved in reserve): `tools/release.py --apply` sets `"status": "published"` and `"released"` (the date the menu shows). If the menu is still short after that, new tests are published directly (no `status`).
- New tests for review are built only while fewer than 4 held tests are unapproved, so they don't pile up.
- `python3 tools/release.py [--json]` applies these rules and says what to release and whether to build (`publish`, `review` or `none`). The nightly routine and the `overnight` skill follow it; so does a test built on request unless David says otherwise. Uncompleted counts (`tools/progress.py`) only count published tests.

## Practice focus: tables with totals and missing numbers (David, Nov 2026)
David's son found Test 63 Thinking Q2 (quiz scores table: rows and columns with totals, some numbers missing) hard. The sums were easy; it was the idea of the totals and how to start that he didn't get. He wants to see this question type repeated until it clicks.
- **How often:** one in about every second test, starting at Test 65, for 4 questions (so roughly Tests 65, 67, 69 and 71). Count the earlier ones by the label "totals table" in the `thinking`/`maths` labels of each `content/vNN.json`. After 4, go back to the normal rotation and ask David whether he wants more.
- **Where:** usually Thinking Q2, the table slot. Sometimes put it in Maths Q1 or Q2 (with A–E options) for variety. It doesn't use up the question-bank slot.
- **Build up slowly**, one step harder each time, with a new context each time (for example books read, money raised at a stall, pets in each class, fruit sold each day):
  1. One gap in each row or column, so each one is a single subtraction, and the question asks for the grand total. The explanation shows that the row totals and the column totals add up to the same grand total.
  2. A two-step chain, like Test 63: filling one gap opens up another.
  3. A gap that can only be found through the grand total (for example a row total that is missing).
  4. A three-step chain or a two-way table (for example boys and girls in each class, with totals), as the stretch question.
- **Same method, same words, every time.** Every explanation starts with this method: "Find a row or column with only **one** number missing. Total − the numbers you know = the missing number. Fill it in, then look again: a new row or column may now have only one gap." Show the completed table with each filled-in number marked in the order it was found (①, ②, ③). The traps come from real mistakes: adding the total into the sum, taking a number from the wrong row, answering with the first number found instead of the one asked for, or stopping one step early.
- Label each one in `content/vNN.json` with "totals table" (for example "Totals table: books read, two-step chain"), and use the category "Tables & timetables" (Thinking) or "Graphs & data" (Maths) as usual.

## Crown Quest: the adventure game at `prac2/` (David, Nov 2026)
A second, separate way to practise the same skills, built as a game so the child wants to keep going. The practice tests and their menu stay exactly as they are; the menu does not link to the game.
- **Where:** `prac2/index.html` (generated; never hand-edit). Sources: `game/template.html` (engine) and `game/content/reading.js`, `thinking.js`, `maths.js` (one world each). `python3 tools/build_game.py` builds it (`tools/build.py` runs it too); `node tools/check_game.js` checks the content rules and plays every level in a browser. Both run in the automatic checks.
- **Shape (agreed with David):** an adventure map of three worlds (Story Forest = reading, Puzzle Peaks = thinking, Number Reef = maths). Each world has 4 to 6 levels of 4 questions (Story Forest and Number Reef have 6, Puzzle Peaks 4; a `long: true` reading level has one long passage and 6 questions), climbing from warm-up to the hardest third of the sample papers, then a boss of 5 stretch questions. A wrong answer gives a hint and a second go (2 gems first time, 1 after the hint; no lives). 2 stars unlock the next level; all but 3 of a world's stars wake its boss (9 of 12 with four levels, 15 of 18 with six); beating a boss wins a crown. Missed questions come back in the Comeback Cave. Ranks, badges and day streaks reward coming back.
- **Questions are new, never taken from the tests** (David's choice), and no live AI runs in the game. They follow the same rules as the tests: Calibration, Reading, Thinking Skills, Maths and Quality rules above (traps from real mistakes, correct option never the single longest, letters spread within a level, verified by computation and an independent cold solve). Reading/Thinking have options A–D, Maths A–E. Every question needs `id` (never reuse or change one: saved progress is keyed on it), `cat` (a label from `CATEGORIES` in `tools/build.py`), `hint` (a nudge that doesn't give the answer) and `explain` (method plus a `why-not` paragraph). Explanations can't refer to option letters only by letter where the options are pictures; describe them.
- **Audit against the sample papers (Nov 2026):** David reviewed every question on a dashboard and approved changes: Word Glade became a four-gap cloze passage, a missing-sentences level was added to Story Forest (`bank: true` = the same five sentences are the options for every gap), and chart questions replaced plain sums (picture graph, dot plot, two-series column graph, bus timetable). The game was short of graphs, tables and scales (about 1 maths question in 5 in the samples): keep that share up when adding questions. He also approved a four-question maths level, "Chart Cove" (target graph, graph with no scale, two gauges with different scales, a results table), placed fourth in Number Reef. `game/drafts/alternates.js` keeps the original drafts for reference; the only one not used is a cube-counting replacement for the painted cube, which David chose to keep. He found the "which extra clue fixes the order" boss question too hard: don't use that type in the game.
- **Gaps closed after David asked whether the game really prepares for the test (Nov 2026):** "Shape Shoals" (Number Reef level 3: symmetry on a grid, right angles inside a shape, a compass walk on a map, perimeter of an L-shape) and "The Long Road" (Story Forest: a 540-word story with six questions, for stamina). A timed "speed run" mode (replaying a passed level against the clock with no hints) was built at the same time and **David turned it down before it was published: don't add timers or speed modes to the game** unless he asks. Still true: the game is a skill-builder and motivator, not a substitute for the numbered tests and timed full papers.
- **Adding more:** add levels before a world's boss, or a new world file (add it to `ORDER` in `tools/build_game.py`). Keep the order easy → hard. Reading topics must be new here too (check the lists in Reading above and the passages already in `game/content/reading.js`).
- **Fortnite time (David, Nov 2026):** the reward is time on Fortnite, shown as a pie chart on the map (and a small one while playing) that grows with every right answer. Getting every question right first time earns exactly **1 hour**; right after a hint earns half that question's share, and a later first-time answer (replay or Comeback Cave) tops it up. Shares follow difficulty: a level-n question weighs n and a boss question weighs twice the number of levels in its world. The engine rescales the shares so the total stays one hour when levels are added (`TIME` in `game/template.html`). The "For grown-ups" panel has buttons to record time already used.
- **Look:** a bold battle-royale style (chunky italic capitals, rarity colours Common → Legendary for the levels). **Fortnite art (David, Nov 2026: he has permission for a private fan work):** the three bosses are Fortnite characters (Hybrid, Raven, Leviathan) and each rank unlocks an outfit in the "Locker" (Recruit → Midas; `SKINS` in `game/template.html`). The pictures are Epic's outfit renders in `prac2/art/*.webp` (committed, not generated; fetched from fortnite-api.com, because Epic's own public API at api.fortnite.com has no artwork). **Our own 3D art (Nov 2026):** the golden crown and the three floating islands (forest, peaks, reef) the treasure chest beside the time pie (five pictures, `chest0` empty to `chest4` overflowing at the full hour) and the backdrop of each boss fight (`arena-forest`, `arena-peaks`, `arena-reef`; the boss stands on the glowing platform) are original models rendered with Blender by `game/art/render.py` (`pip install bpy` in a scratch venv, `python game/art/render.py OUT_DIR`, then `python game/art/pack.py OUT_DIR` trims them into `prac2/art/*.webp`). Blender runs in the cloud session; David's own machine isn't needed. Keep the fan-content notice at the foot of the page ("not official and not endorsed by Epic"), keep the project non-commercial, and don't use Epic's logo or fonts.
- **Practice from the admin page:** the admin page has a "Crown Quest" card whose **Practice** button opens `prac2/index.html?admin=1`. After the PIN (same `prac.admin` session flag as the tests) the game opens with every level unlocked, starts from nothing and saves nothing, so the child's real progress is untouched. Keep this working when changing the engine (`check_game.js` tests it).

- **Shape (David's second round, Nov 2026: "more Fortnite-like"):** 100 players. He rides the Battle Bus and taps where to land; the other 99 drop onto the island (white dots), and an elimination feed shows them knocking each other out as he plays. The storm closes four times (circle centres move; anyone outside is caught or rotates in): 50 players are left after circle 1, 20 after circle 2, and only he and the boss after circle 3. **Each of circles 1 to 3 has one reading, one thinking and one maths opponent, and all three must be beaten before the storm closes** (the gate). The opponent strafes, jumps your shots, builds walls, aims (a red line: jump or build), throws grenades (move or jump) and stops to heal (+10; hit them to interrupt). **Its hits are small and the arena can never knock you out** (it stops at 1 health): only wrong answers can. **Reading:** a reading opponent has one bar for each question on its passage and only right answers knock bars off; after the whole passage comes one bigger showdown with 2 shots per right answer, where hits charge your shield. ## Calibration
- Every question must be at genuine OC level and test a skill that appears in the samples.
- Write fresh questions that test the same skills as the samples, sometimes in a similar way, sometimes in an unexpected way. Never reword a sample question.
- Weight question types by how often they appear in the samples (frequencies below), favouring the skills that win the most marks.
- Each version, include new skills and also loop back to skills from earlier versions.

## Reading
Sample paper: story 6 Qs, cloze 8, poem 5, missing sentences 6, four extracts 8.
- Rotate formats. Over any 9 versions aim for about: cloze ×2, four extracts ×2, story ×2, missing sentences ×2, poem ×1.
- Passages stay approachable (about 250–350 words), but questions are genuinely OC-level: implication, why a detail is included, structure, comparisons, feelings shown rather than stated.
- Cloze has 6 gaps (½ mark each; see Format). Spread the deciding clue across collocations, preposition/grammar fit, look-alike words and shades of meaning, with the last gap read from the whole passage (the stretch). Don't let the right answer be the only hard word in its set.
- Cloze uses upper-primary to adult vocabulary like the samples (e.g. culmination, teeming, scouring, remiss): near-synonyms, look-alike words and preposition collocations where only one fits. Avoid easy everyday idioms. No homophone-spelling gaps (bated/baited and the like): the real cloze doesn't test them (David, Oct 2026).
- Every few versions, use a real public-domain classic instead of an original text (author died more than 70 years ago, e.g. Grahame, Nesbit, Stevenson, Lawson). Copy the text exactly from a reliable source (Project Gutenberg via its GitHub mirrors) and credit author and year in the passage note.
- Wrong options must be partly true or built on a real detail from the text, never obviously wrong.
- Every reading topic must be new: check `reading` and `reading_topic` in every `content/vNN.json` **and** `content/used_topics_before_v33.md` (topics from the earlier tests made outside this repo) and the kind of topic the real test uses. The story is never about football.
- In four-extract sets, every extract should be the answer to at least one question where possible.

## Thinking Skills
Sample frequency across 90 questions: spatial 18%, spot the mistake 14%, tables/timetables/data 14%, supports the claim 13%, order/arrangement 12%, whose reasoning 11%, rules/codes/sets 9%, number problems 4%, must/cannot be true 3%.
- **Q1: always critical thinking.** Rotate spot the mistake → supports the claim → whose reasoning, with spot the mistake slightly more often.
  - Spot the mistake: cycle the patterns: ignoring another possible cause; judging from your own small group; treating something needed as a guarantee; an unfair comparison; treating "most" as "all"; reversing a rule. Every option contains "may".
  - Whose reasoning: cycle needed versus guaranteed; reversed rule; "most" leading to "probably"; certainty/worst case.
  - Supports the claim: the right answer backs the claim's reason; the wrong options are true but about something else.
- **Q2:** usually a table, timetable or data question. David finds seating/ordering arrangement questions come up too often: use one at most about once in every 6 versions (check the `categories` for "Order & arrangement").
- **Cover the whole question base.** Every few versions, use Q2 (or Q3) for a type the fixed slots would otherwise miss: rules/codes/sets, number problems, must/cannot be true, and question types next to the samples (for example odd one out, logic grids, sequences of shapes, balance scales, true/false statements from a diagram). Check the `thinking` labels and `categories` in recent `content/vNN.json` files so each type comes round regularly.
- **Q3:** spatial at sample-paper difficulty (one or two clear steps), or a second critical-thinking question. Spatial questions must not be harder than the sample versions.
- No paper-folding questions (fold and punch, folding string) for a while (David, Oct 2026: "had enough of these folding ones"). Use other spatial types: straight cuts on paper, views, nets, cube models, turns and flips, compass directions.
- Never use "weakens the argument" questions (they don't appear in the samples).

## Maths
- **Q1:** a quick-fire question (under a minute), rotating: place value, time, money, measurement, reading a scale, reading a graph, simple word problem, missing number.
- **Q2 and Q3:** multi-step reasoning on sample-paper topics: fractions, patterns, area and perimeter, 3D shapes, chance statements, combinations, rates, best value, timetables, "which statements are correct" graph questions.
- Combinations questions stay simple (David, Nov 2026: "keep these much simpler, like 3 shorts, 3 tops, 2 hats = 3 × 3 × 2"): multiply the choices for each item, with no extra conditions such as "no two the same colour". Traps: adding instead of multiplying, forgetting one item, multiplying two and adding the third. Don't use one as the stretch question.
- At most one competition-style (Kangaroo-like) question per version.
- Repeating patterns must show the repeat clearly (a visible repeating block); no rule-generated sequences whose cycle only shows up after brute-force working (David, Oct 2026).
- Cover the whole question base here too: every few versions, use Q2 or Q3 for a sample topic not seen recently or a nearby one (for example symmetry, angles, position and direction, mass, volume, number puzzles), checking the `maths` labels in recent `content/vNN.json` files.

## Stretch questions
- Every section of every version (Reading, Thinking Skills and Maths) has one stretch question pitched at the hardest third of the sample papers (around Q25–35). Usually make it Q3. ## Quality rules (every question)
- Every wrong option comes from a real mistake a child would make.
- The correct option is never the single longest.
- Spread the answer letters within each section.
- Facts must be accurate; check anything factual before using it.
- Use images and diagrams wherever they help, drawn clearly and not to scale where measuring would give the answer away.
- Explanations show the method and name why each trap is wrong.
